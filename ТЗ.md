# Arsh Party — Техническое задание
Версия: 1.6 | Дата: 29.10.2026 | Статус: сайт и админка работают локально на живой базе; следующий шаг — этап 2

**Что нового в 1.1:** заказы и заявки дублируются в базу данных Supabase; красная звезда утверждена как «Скорая шашлычная помощь» (СШП); цены загружаются отдельным файлом; заложена история заказов с кнопкой «Повторить»; логотип переведён в SVG; стили на CSS Modules вместо Tailwind (причина в разделе 3).

## 1. Суть проекта

Arsh Party («Аршпати») — всё для праздника под одним брендом. Пять направлений, у каждого своя звезда и свой цвет. Сайт решает две задачи: даёт сразу заказать еду с мангала из меню с корзиной и собирает заявки на остальное (СШП, кейтеринг, организация, ведущий). Каждый заказ и каждая заявка сохраняются в базе и сразу приходят владельцу в Telegram. Постоянный клиент заходит, открывает свои прошлые заказы и повторяет любой одной кнопкой.

Слоган из логотипа: **All ready for super holidays!**

**Рынок:** Россия — Рязань и весь Центральный федеральный округ (ЦФО). Валюта — рубли (₽), телефоны в формате +7.

## 2. Вселенная: пять звёзд

| Звезда | Направление | URL | Что делает посетитель | Механика |
|---|---|---|---|---|
| 🟠 Оранжевая | Доставка блюд с мангала | `/mangal` | Выбирает блюда, кладёт в корзину, оформляет доставку | Меню + корзина + заказ |
| 🔴 Красная | **Скорая шашлычная помощь (СШП)** | `/sshp` | Срочно вызывает мангальщика на свою площадку | Короткая заявка, 3 поля |
| 🟢 Зелёная | Событийный кейтеринг (включая фуршет) | `/catering` | Подбирает формат (банкет, фуршет, кофе-брейк), оставляет заявку | Заявка с параметрами события |
| 🩷 Розовая | Организация мероприятий | `/events` | Описывает праздник, получает предложение | Заявка с параметрами события |
| ⚫ Чёрная | Ведущий на мероприятие | `/host` | Смотрит, кто ведущий, проверяет дату | Заявка с датой |

**Решения по структуре:**
- Фуршет — формат внутри зелёной звезды. Розовая — организация мероприятий, как на логотипе.
- Красная звезда утверждена: срочный выезд мангальщика с мангалом и мясом к клиенту. На сайте полное название «Скорая шашлычная помощь», короткое «СШП» используется в меню, на кнопках и в адресе `/sshp`.
- Звёзды связаны: после заказа или заявки сайт предлагает соседние звёзды.

## 3. Стек технологий

| Слой | Технология | Зачем |
|---|---|---|
| Фреймворк | **Next.js 15 (App Router) + TypeScript** | Серверный рендер для SEO, API-роуты, деплой на Vercel |
| Стили | **CSS Modules + глобальные CSS-переменные** | См. примечание ниже |
| Анимации | **CSS transitions и keyframes** | Все анимации простые, библиотека не нужна; учитывается `prefers-reduced-motion` |
| Корзина | **useState** + localStorage | Корзина переживает перезагрузку; отдельная библиотека не понадобилась |
| Валидация | **Zod** | Одни схемы на клиенте и на сервере |
| База данных | **Supabase (Postgres)** | Хранит заказы и заявки, даёт историю и повтор заказа |
| Уведомления | **Telegram Bot API**, метод `sendMessage` | Мгновенное уведомление владельцу |
| Шрифты | **Unbounded** (заголовки), **Onest** (текст) через `next/font` | Близко к логотипу, кириллица, без внешних запросов у посетителя |
| Хостинг | **Vercel** | Деплой из GitHub |

**Примечание о смене Tailwind на CSS Modules.** Фирменные элементы бренда (плашка неправильной формы, повёрнутая лента, звезда в букве) всё равно пишутся вручную через `clip-path` и `transform`, так что Tailwind здесь мало помогает. Без него на две зависимости меньше и стили проще проверять. Решение обратимо: если хотите Tailwind, переведу без изменения дизайна.

**Зависимости по этапам:** этап 1 — только `next`, `react`, `react-dom`, `typescript`; этап 3 — `zustand`, `zod`; этап 4 — `@supabase/supabase-js`.

```
   ├─ lib/                    # telegram.ts, supabase.ts, schemas.ts, client-id.ts
   └─ store/cart.ts           #                                    (этап 3)
```

**Главная идея:** все пять направлений рендерятся одним шаблоном. Различия описаны в `content/directions.ts`. Новая звезда добавляется одной записью.

**Поток заказа:**
```
Посетитель → форма (Zod) → POST /api/order
  → проверка Zod на сервере, цены пересчитываются по prices.json
  → запись в Supabase (orders)
  → сообщение в Telegram, флаг telegram_sent = true
  → ответ с номером заказа → экран «Спасибо»
```
Если база недоступна, заказ всё равно уходит в Telegram. Если не отвечает Telegram, заказ остаётся в базе. Ошибку видит посетитель только тогда, когда не сработало ни то, ни другое.

Ключи Telegram и Supabase хранятся только в переменных окружения сервера. Браузер с базой напрямую не общается.

## 5. История заказов и «Повторить»

**Версия 1 (закладываем сейчас, работает без входа):**
- При первом визите браузер получает случайный `client_id` (UUID) и хранит его в localStorage.
- Каждый заказ уходит на сервер вместе с `client_id`.
- Страница «Мои заказы» запрашивает `GET /api/orders?client=<id>` и показывает последние 10 заказов.
- Кнопка «Повторить» кладёт те же блюда в корзину по **текущим** ценам. Блюда, которых больше нет в меню, пропускаются, и посетитель видит об этом строку.
- Имя, телефон и адрес из последнего заказа подставляются в форму автоматически.

**Ограничение версии 1:** история привязана к браузеру. С другого телефона или после очистки данных её не будет.

**Версия 2 (позже):** вход по номеру телефона. Заказы с тем же телефоном собираются в одну историю на любом устройстве. Способ подтверждения номера (SMS, Telegram, звонок) выберем отдельно: у SMS есть стоимость за сообщение.

## 6. Цены отдельным файлом

- Меню (`content/menu.ts`) хранит блюда без цен: id, название, вес, категория, фото.
- Цены лежат в `content/prices.csv` в две колонки: `id;price`. Файл можно вести в Excel или Google Таблицах и сохранять как CSV.
- Команда `npm run prices` проверяет файл и собирает `content/prices.json`. Блюда без цены и цены без блюда выводятся списком предупреждений.
- Пока цены нет, карточка показывает «Цена уточняется», а итог корзины — «Сумму подтвердим по телефону». Заказ всё равно можно оформить.

## 7. Дизайн-система

**Принцип:** белое поле, чёрная плашка неправильной формы, цвет звезды как единственный акцент. Остальное молчит.

**Цвета — из брендбука `arsh_logo - коды цвета.pdf`:**

| Токен | RGB | CMYK (для печати) | Роль |
|---|---|---|---|
| `--ink` | `#000000` | C95 M95 Y45 K95 | Плашки, текст, чёрная звезда |
| `--c-orange` | `#FF6600` | C0 M69 Y97 K0 | Мангал |
| `--c-red` | `#FF0000` | C0 M95 Y100 K0 | СШП, главный логотип |
| `--c-green` | `#33CC33` | C67 M0 Y89 K0 | Кейтеринг |
| `--c-pink` | `#FF0066` | C1 M91 Y42 K0 | Организация |
| `--c-blue` | `#0B3B8C` (тёмная тема и подвал `#4F86F7`) | — | Звезда ведущего: глубокий синий по решению владельца |
| `--paper` | `#FFFFFF` / тёмная тема `#0C0C0D` | — | Фон |
| `--accent` | цвет текущей звезды | — | Звезда в логотипе, кнопки, искры |

**Контраст.** У белого текста на `#FF0000` контраст около 4:1, это ниже 4.5:1 для обычного текста по WCAG 2.2. Поэтому на красном и оранжевом пишем только крупный жирный текст (от 18.66px bold), как в ленте логотипа.

**Типографика:** Unbounded 700–800 для заголовков (40px на телефоне, до 104px на десктопе), Onest 400–600 для текста, в контенте минимум 16px.

**Фирменные элементы:**
- **Plate** — чёрная плашка через `clip-path: polygon(...)`: левый край срезан, верх слегка уходит вверх вправо. Текст внутри стоит прямо.
- **Ribbon** — лента цвета акцента, повёрнута на −2°, выступает за левый край плашки, капс с разрядкой.
- **Star** — пятиконечная звезда цвета направления, единственный декор.
- **Логотип** — `public/brand/arsh-party.svg`, получен трассировкой главного логотипа (JPG 1280×668). Для сайта точности хватает. Для печати крупного формата нужен вектор от дизайнера.

**Искры огня в hero** (по желанию владельца, идея из старого `arsh-party.html`). Реализация: один `<canvas>` и `requestAnimationFrame` (`src/lib/fire-particles.ts`), не больше 26 частиц на телефоне и 48 на десктопе, пауза вне экрана и в свёрнутой вкладке, полное отключение при «Уменьшить движение». Цвет искр следует за выбранной звездой. Замер в Chromium: 59–61 кадр/с.

**Микроанимации (все ≤ 300 мс, отключаются при `prefers-reduced-motion`):** перетекание акцента при выборе звезды, подъём карточки и поворот звезды при наведении, пружинящий счётчик корзины, листы снизу.

**Mobile first:** проектируем от 375px, тап-зоны от 44×44, главное действие в зоне большого пальца, тёмная тема с первого коммита.

## 8. Экраны и компоненты

### 8.1 Главная `/` — готова
- **Хедер:** логотип, разделы страницы для быстрого перехода (Направления, О нас, Отзывы, Заявка, Соцсети, Контакты) с подсветкой текущего, городской телефон на широких экранах. На телефоне разделы листаются вбок в той же строке.
- **Hero:** главный логотип Arsh Party. Звезда в букве A и лента со слоганом меняют цвет при выборе направления. Рядом созвездие из пяти кнопок и строка о выбранном направлении. Снизу поднимаются искры в цвет звезды. На десктопе две колонки, на телефоне одна.
- **Пять карточек направлений:** логотип направления на белой плитке (у ведущего — фото Арша с микрофоном), звезда, название, строка пользы, теги, действие.
- **О проекте:** чёрно-белый портрет Арша, история «в духе Гая Ричи» (текст из старого сайта), цифры (200+ мероприятий, рейтинг Яндекс Карт, 5 направлений), три фото с мероприятий.
- **Отзывы:** рейтинги площадок со ссылками (Яндекс Карты 4,8 / 54 оценки, 2ГИС 4,6 / 27 оценок на 29.10.2026) и лента из 11 отзывов. Тексты дословные, у каждого автор, дата и ссылка на площадку. На устройствах с мышью лента едет сама и замирает при наведении, на телефоне листается пальцем.
- **Как это работает:** три шага.
- **Заявка** (`#order`): выбор направления звёздами, имя, телефон, способ связи (звонок / WhatsApp / Telegram), город с подсказками городов ЦФО, дата, число гостей, комментарий, согласие на обработку данных. Карточки направлений и кнопка в hero ведут сюда по якорю `#order-<направление>` и сразу выбирают звезду. Пока форма на экране, плавающие кнопки прячутся.
- **@arshparty:** блок соцсетей ВКонтакте и Instagram* (Telegram-канал включается одной строкой). С ключами показывает по 3 свежих поста из каждой сети с обновлением раз в 15 минут, без ключей — фирменные карточки профилей. Сноска про Meta.
- **Искры по краям экрана:** после hero у левого и правого края мерцают искры в цвет выбранной звезды, при прокрутке их больше и они отстают от страницы.
- **Связаться:** звонок, WhatsApp, Telegram (Instagram и ВКонтакте появятся, когда будут ссылки), адрес самовывоза и часы.
- **Плавающие кнопки:** WhatsApp, Telegram и красная кнопка звонка в правом нижнем углу на всех страницах.
- **Футер:** всегда чёрный (в светлой и тёмной теме): направления, контакты, адрес, часы.

## 9. Пользовательский путь

### Сценарий 1: «Хочу шашлык домой» (оранжевая)
Меню → 3 блюда в корзину → имя, телефон, адрес → заказ в базе и в Telegram → «Заказ принят».
Точки отвала: нет фото, непонятна зона доставки, длинная форма. Решение: зона над меню, три обязательных поля.

### Сценарий 2: «Повторить прошлый заказ» (новый)
Пользователь: заказывал в прошлую пятницу, хочет так же.
Точка входа: главная → «Мои заказы».
Шаги:
1. Видит прошлый заказ → «Повторить».
2. Корзина уже собрана, контакты подставлены → «Заказать».
3. «Заказ принят».
Успешный финал: заказ за два нажатия.
Точки отвала: история пропала после смены телефона. Решение: версия 2 со входом по номеру.

### Сценарий 3: «Гости едут, рук нет» (СШП)
«Приедем и пожарим» → телефон, адрес, когда → «Перезвоним за N минут». Только три поля.

### Сценарий 4: «Корпоратив на 40 человек» (зелёная)
Форматы → дата, гости, формат, бюджет → «Предложение в течение дня». Нужна строка «от N ₽ на гостя».

### Сценарий 5: «День рождения под ключ» (розовая)
Что берём на себя → дата и гости → звонок. На «Спасибо» предлагаем кейтеринг и ведущего.

### Сценарий 6: «Нужен ведущий» (чёрная)
Фото, видео, отзывы → «Проверить дату» → ответ сегодня. Нужны материалы владельца.

## 10. База данных (Supabase)

Файл `supabase/schema.sql`. Две таблицы, доступ только с сервера через service role key, RLS включён без публичных политик.

**orders**
| Поле | Тип | Описание |
|---|---|---|
| id | uuid, pk | |
| number | bigint, identity | Короткий номер для общения: «Заказ №128» |
| client_id | uuid | Браузер клиента, для истории |
| name, phone, address | text | |
